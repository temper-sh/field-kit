# Conduct the investigation

Find useful presets for this machine and return evidence that improves the
catalog. Decide from the goal, prior evidence and observations. The study brief
supplies context, not a sequence to exhaust.

## Orient and prepare

Read existing study state, brief, results and repairs before starting new work.
Run ./field-kit doctor and use installed Temper. Read [Temper operations](TEMPER.md)
before relying on newer commands.

Consult [relevant studies](../studies/README.md), current Results/catalog
assessments and primary upstream sources. Record important expectations and
their source/revision or access date. Distinguish facts and hypotheses.
Reuse applicable evidence. Software refreshes focus on changed material.

Write a brief covering intended work, candidates and why, prior observations,
open questions, comparisons, material/resource budget and evidence destination.
Prepare Temper presets and exact locks. Include useful drafts/variants within
approval. Review installation requirements and unknown costs. On the owner's
machine, an engine build or setting Temper cannot express yet can be declared as
a [local engine](TOOLS.md#evaluate-a-local-engine-before-temper-supports-it);
its results are research evidence for deciding whether Temper should support it.

Use study init --preview to prepare a concrete review. Pass --authoring-root
when candidates are user presets there, so Temper checks them. Choose the
weights cache: the user's default, or a research cache on another disk with
--weights-cache, usually with --weights-cleanup keep. The preview names any
running layout that Field Kit will stop and restore. Obtain approval once,
then initialize with --yes. Choose limits for the actual investigation.

Tell the tester: while Field Kit runs, do not use Temper, and close other AI
apps. Point them to the study's restore.md for returning to normal work.

## Investigate

Follow [the method](METHOD.md). Generate or write workloads and give every trial
a reason tied to the question. Use established harnesses for finished tasks;
inspect patches, tests and deliverables. Exit status alone is not quality.

Keep the brief's decisions and next question current after meaningful results.
Read compact results before raw logs. Diagnose surprises using the cheapest
check that distinguishes plausible causes. Match controls to explain an
effect; independently tuned candidates answer deployment-choice questions.

Prefer the host's foreground job completion. For detached work use study wait
and let the host wait on that process. Internal sampling needs no agent turns.
Return to interpret completion, repair a defect or respond to a resource stop.

Follow [repair instructions](REPAIR.md) instead of stopping on routine defects.
A broken evaluator does not erase unaffected measurements. Coding failures
do not block independent resource/cache work.

## Return

Write conclusions.md beside the study: selected exact runs/locks, hardware,
quality review, elapsed time/native rates, loaded/peak memory with counters,
tested input/output/cache scope, meaningful alternatives, remaining questions
and why exploration stopped. Budget exhaustion is not a hardware limit.

Prepare evidenced settings for Temper. Results owns maintained comparison
tables; return usable observations and interpretation.

Attach every defect/repair through the repair command, including local patches.
Close owned resources and export. An idle open study may be exported for a
blocked handoff, with remaining cleanup explicit. Nothing sends automatically.
Tell the tester exactly which archive to return.
